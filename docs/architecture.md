# EveryDoing 아키텍처와 브라우저 개발 모드

작성일: 2026-11-10

## 기존 구조

- Windows 데스크톱 앱: Tauri 2 / Rust 백엔드, `static/`의 HTML·CSS·바닐라 JavaScript 화면.
- Rust 인덱서가 선택된 경로와 확장자에 따라 파일을 읽고 수정일별로 묶는다. 드라이브 루트는 MFT, 일반 폴더는 `walkdir`을 사용한다.
- 앱 데이터는 사용자별 설정 디렉터리의 `EveryDoing` 아래에 저장된다. AI 요약은 선택 기능이다.

## 결정: 로컬 브라우저 개발 모드

시연과 개발 검증을 위해 기존 화면을 그대로 제공하고 실제 로컬 폴더를 스캔하는 별도 로컬 서버를 추가한다. 기존 배포용 Tauri 앱을 웹 제품으로 대체하지 않는다. 별도 서버는 `127.0.0.1`에만 연결하고, 실제 Rust 인덱서의 폴더 순회 및 MFT 로직을 재사용한다. 브라우저와 서버 사이의 명령·이벤트 어댑터는 개발 모드에서만 주입한다.

- 브라우저 모드의 설정·캐시·메모는 전용 개발 디렉터리에 저장하며 데스크톱 사용자의 데이터와 섞지 않는다.
- 폴더 스캔은 실제 디스크를 읽는다. 드라이브 루트 MFT 스캔에는 데스크톱 앱과 마찬가지로 관리자 권한이 필요하다. 기존 앱의 색인 캐시는 설정이 일치할 때 읽기 전용으로 가져올 수 있다.
- 파일 열기는 실제 스캔 결과로 확인된 파일에만 제한한다.
- 외부 사이트에서 로컬 명령을 호출하지 못하도록 요청 출처 및 세션 인증을 검증한다. 서버는 공용 네트워크에 노출하지 않는다.
- AI 전송은 별도 구현·검증하기 전에는 지원하지 않음을 화면에서 알린다. 데스크톱 앱 AI 동작을 대체하거나 성공한 것처럼 모의하지 않는다.
- 저장·스캔·검색은 사용자의 지정 경로와 실제 파일을 사용하며, 자동 테스트에서는 별도 임시 디렉터리를 사용한다.
- 데스크톱 개발 실행 파일은 `--preview-data-dir <절대경로>`를 지정하면 해당 폴더를 설정·캐시·메모 저장소로 사용한다. 이 옵션은 디버그 빌드에서만 동작하며, 배포 빌드는 기존 사용자 데이터 위치를 유지한다.

## 프런트엔드와 품질 검증

기존 단일 페이지, 전역 CSS, 바닐라 JavaScript의 로컬 상태 및 Tauri 커맨드 모델을 유지한다. 브라우저 개발 모드에서만 어댑터가 명령을 로컬 서버로 전달한다. 테스트는 실제 임시 파일을 대상으로 스캔, 저장, 캐시 무효화, 잘못된 접근 차단을 확인하고 화면을 별도로 검증한다. 사용자 파일은 테스트로 수정하거나 삭제하지 않는다.
