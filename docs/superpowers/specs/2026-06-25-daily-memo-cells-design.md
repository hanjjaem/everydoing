# 업무 일지 — 다이어리 칸 (날짜별 한 줄 메모) 설계

날짜: 2026-06-25

## Context

이 앱의 목적은 "지난달 내가 언제·무엇을·얼마나 했는지"를 달력에서 파악하는 것이다.
사용자 인터뷰에서 드러난 핵심 문제: 현재 화면이 **"멍청해 보인다"**. 큰 칸 35개에
숫자 하나씩만 담겨 정보 밀도가 낮고, 칸을 통째로 칠한 히트맵은 (1) 빨강이 "경고"로
읽히고 (2) 글씨를 얹을 수 없으며 (3) 한 작업을 납작한 색 하나로 뭉개 다이어리답지
않다.

사용자가 원하는 것은 감정(뿌듯함)이 아니라 **파악**이다. 그리고 빈 여백에
**그 날을 정리하는 한 줄 메모**를 직접 적고 싶어한다 — AI 생성이 아니라 본인이.
이 한 줄이 들어오면 칸이 비로소 말을 하고, 큰 칸이 "다이어리 한 칸"으로 정당해진다.

목표: 칸을 **숫자 + 점(밀도) + 내 한 줄 메모**를 담는 다이어리 칸으로 바꾼다.
히트맵(전체 칠)은 버린다. 완전 로컬 유지(외부 AI·네트워크 없음).

## 설계 결정

### 칸 구조 (다이어리 한 칸)
- **좌상단**: 날짜 (작은 캡션으로 물러남)
- **우상단**: 파일 수 숫자. 많을수록 굵고 진하게(요소 추가 없이 숫자 자체로 강조).
  → **클릭 시 우측 드로어**에 그 날 파일 목록 (기존 동작)
- **숫자 아래**: 점(tally) — 문서 1개당 점 1개, 상한까지(예: ••••+). 한눈에 보는 밀도.
  박스·테두리 없음(과거 "N개" 배지가 AI 티의 주범이었으므로 재발 방지)
- **본문 여백**: 내 한 줄 메모. → **클릭 시 그 자리에서 인라인 입력/수정**
- **빈 날**: 아무것도 강요하지 않음, 조용히 비어있음

### 칸 안의 두 클릭 분리 (충돌 방지)
- **숫자 클릭** → 파일 드로어 (무엇을 했나)
- **여백 클릭** → 메모 편집 (어떤 하루였나)

### 히트맵 제거
- `data-heat` 배경색(전체 칠)과 `--heat-*` 변수 제거.
- 활동량은 숫자 강조 + 점으로만 표현. 칸 배경은 메모가 잘 읽히도록 균일.

### 메모 저장 (완전 로컬)
- `memos.json`에 날짜별 한 줄 저장: `{ "2026-06-25": "예산안 검토, 보고서 초안" }`
- 데이터 파일이므로 `.gitignore`에 추가.
- 빈 문자열 저장 시 해당 날짜 키 삭제(빈 메모를 남기지 않음).

## 변경 파일

### `everything_client.py`
- `load_memos(path="memos.json")` — 파일 없으면 `{}` 반환.
- `save_memos(memos, path="memos.json")` — `save_config`과 동일 패턴(UTF-8, indent).
- `set_memo(memos, date, text)` — 순수 함수. text가 공백이면 키 삭제, 아니면 set.
  새 dict 반환(기존 불변). 테스트 가능하게 분리.

### `server.py`
- `GET /api/memos` → 현재 memos dict 반환.
- `POST /api/memos` (body `{date, text}`) → `set_memo`로 갱신 후 `save_memos`, `{ok:true}`.
  - `do_POST`의 허용 route 집합에 `/api/memos` 추가.

### `static/index.html`
- 히트맵 CSS(`--heat-*`, `.cell[data-heat=...]`) 제거.
- 점(`.dots`)·메모(`.memo`) 스타일 추가. 숫자(`.count`)에 양별 강조용 단계 클래스.
- 메모 인라인 편집용 스타일(편집 중 textarea/contenteditable 느낌, 박스 최소화).

### `static/app.js`
- `render()`:
  - `data-heat` 부여 제거.
  - 숫자(`.count`) 클릭 → `selectDate`(드로어). 셀 전체 onclick은 메모 편집으로 변경.
  - 점 렌더: 파일 수만큼(상한 적용) 점 생성. `dotCount(n)` 순수 함수로 상한 로직 분리.
  - 메모 표시: `memos[cellKey]` 있으면 본문에 한 줄 표시.
- 메모 편집: 여백 클릭 → 인라인 입력 활성 → blur/Enter 저장 →
  `POST /api/memos` → 로컬 `memos` 갱신 → 해당 칸만 갱신.
- `load()`에서 `/api/files`와 함께 `/api/memos`도 가져와 전역 `memos`에 보관.

## 백엔드 외 영향 / 검증

### 테스트 (`tests/test_everything_client.py`)
- `set_memo`: 추가 / 덮어쓰기 / 공백이면 키 삭제 / 원본 불변.
- `load_memos`: 파일 없을 때 `{}`.
- `save_memos`+`load_memos` 라운드트립.

### 수동 검증 (`python server.py` 후 브라우저)
1. 칸 여백 클릭 → 그 자리에서 메모 타이핑 → 저장 → 칸에 한 줄 표시.
2. 새로고침/창 복귀 후에도 메모 유지(로컬 저장 확인).
3. 숫자 클릭 → 드로어에 파일 목록(메모 편집과 충돌 없음).
4. 점 개수가 파일 수에 따라 늘고 상한에서 `+` 처리.
5. 히트맵 색이 사라지고 메모 글씨가 또렷이 읽히는지.
6. 빈 메모 저장 시 `memos.json`에서 키가 사라지는지.
7. `git status`에 `memos.json`이 안 잡히는지(gitignore 확인).
