# 업무정리캘린더 — 설계 문서

작성일: 2026-06-25

## 목적

내가 진행한 업무를 **캘린더 형태**로 한눈에 보기 위한 개인용 로컬 웹.
지정한 위치에 저장된 업무 문서 파일들을 **수정일 기준**으로 달력 칸에 배치해,
"언제 무엇을 했는지"를 월 단위로 파악한다.

## 핵심 결정 요약

- **인덱스 엔진은 Everything 재활용** — 직접 파일 시스템을 스캔하지 않는다.
  이미 설치된 Everything의 HTTP 서버 기능을 켜서 쿼리한다. (전 드라이브 인덱싱·실시간 갱신을 Everything이 담당)
- **우리 서버는 Python 표준 라이브러리**로 만든 얇은 로컬 서버.
- **데이터는 시작 시 한 번에 전체 로드** 후 브라우저 메모리에 보관. 월 이동 시 재요청 없음.
- 기준 날짜는 **파일 수정일**. 범위는 **지정 위치 + 문서 확장자**로 필터.

## 아키텍처 & 데이터 흐름

```
[브라우저: 캘린더 UI]
      │  ① 시작 시  GET /api/files   (월 구분 없이 전체)
      ▼
[Python 로컬 서버]  (http.server)
      │  ② Everything 쿼리 조립 후 HTTP 요청
      ▼
[Everything HTTP 서버]  localhost:포트  →  JSON 결과
      │  ③ 파일 목록(name, path, date_modified) 반환
      ▼
[Python 서버]  ④ 날짜별로 묶고 FILETIME→일반날짜 변환 → JSON 응답
      │            { "2026-06-12": [파일들...], "2026-05-03": [...] }
      ▼
[브라우저]  ⑤ 메모리에 보관, 월 단위로 그림. 월 이동은 재요청 없이 즉시.
            파일 클릭 시 POST /api/open {path, mode:"file"|"folder"}
```

### 구성 요소

1. **Everything HTTP 서버** — 우리가 만들지 않음. 사용자가 Everything 옵션에서 HTTP 서버를 켠다.
2. **Python 로컬 서버** (구현 대상)
   - 정적 파일(캘린더 HTML/JS) 서빙
   - `GET /api/files` — Everything에 쿼리 → 날짜별 묶음 JSON 반환
   - `POST /api/open` — 파일/폴더 열기 (`os.startfile`, 폴더는 탐색기에서 선택 상태로)
3. **브라우저 캘린더 UI** (구현 대상) — 월 달력 + 칸별 개수 + 클릭 펼침 + 파일 클릭 메뉴

### 핵심 데이터 변환

Everything이 주는 수정일은 윈도우 FILETIME(1601 기준 100ns 단위)일 수 있다.
Python 서버에서 일반 날짜(YYYY-MM-DD)로 변환해 "어느 날 칸"인지 정한다.
브라우저는 이미 정리된 날짜별 묶음만 받는다.

## 설정 (`config.json`)

코드를 건드리지 않고 이 파일만 수정한다.

```json
{
  "everything_host": "localhost",
  "everything_port": 8080,
  "scan_paths": [
    "C:\\Users\\user\\Desktop",
    "C:\\Users\\user\\Documents",
    "C:\\Users\\user\\Downloads"
  ],
  "extensions": ["hwp", "hwpx", "doc", "docx", "xls", "xlsx", "ppt", "pptx", "pdf"],
  "server_port": 5000
}
```

## Everything 쿼리 조립

시작 시 **날짜 필터 없이** 전체를 한 번 가져온다(경로 + 확장자 조건만).

- **경로 필터** — `scan_paths`를 OR로 묶음: `("C:\...\Desktop\" | "C:\...\Documents\" | ...)`
- **확장자 필터** — `ext:hwp;hwpx;docx;...` (세미콜론 구분)
- **파일만** — 폴더 제외
- 요청 필드(JSON) — 파일명, 전체경로, 수정일

조립 예: `ext:hwp;hwpx;docx;... ("C:\...\Desktop\" | "C:\...\Documents\")`

**전체 로드 채택 이유** — Everything 쿼리는 빠르지만, 전체를 한 번 받아두면 월 이동 시 왕복이 없어
체감이 더 매끄럽다. 데이터는 위치·확장자로 걸러져 양이 작을 가능성이 높다.

**안전장치(YAGNI)** — 결과가 수만 건 이상이라 최초 로드가 무거우면, 그때 "최근 N개월만" 상한을 추가한다.
지금은 전체 로드로 시작한다.

## UI 동작

**화면 구성** — 상단에 `◀ 2026년 6월 ▶` 월 이동 + `새로고침` 버튼, 하단에 7열 달력 그리드.

**날짜 칸**
- 파일 있는 날: **개수 배지**(예: `3개`).
- 칸 클릭 → 그날 파일 목록 **펼침**(파일명·확장자 표시).
- 파일 없는 날: 빈 칸.
- 오늘 날짜: 살짝 강조.

**파일 클릭 메뉴** (펼친 목록의 파일명 클릭 시)
- **파일 열기** → `POST /api/open {path, mode:"file"}` → 연결 프로그램으로 실행
- **폴더 열기** → `mode:"folder"` → 탐색기에서 파일 선택된 채로 열림
- **경로 복사** → 서버 호출 없이 클립보드 복사

**월 이동** — 전체 데이터를 이미 보유하므로 `◀ ▶`는 재요청 없이 즉시 다시 그림.

**새로고침** — 누르면 전체를 다시 가져온다(Everything이 실시간 인덱싱하므로 항상 최신).

## 에러 처리

우회하지 않고 원인을 화면에 분명히 알린다.

- **Everything HTTP 서버 연결 실패** — "Everything HTTP 서버에 연결할 수 없습니다.
  Everything → 도구 → 옵션 → HTTP 서버를 켰는지, 포트가 config.json과 맞는지 확인하세요."
- **결과 0건** — 빈 캘린더 + "이 조건에 맞는 파일이 없습니다. scan_paths·extensions를 확인하세요."
- **파일/폴더 열기 실패**(삭제·이동됨) — 항목 옆에 "파일을 찾을 수 없습니다", 앱은 죽지 않음.
- **날짜 변환 실패** — 수정일이 없거나 형식이 이상한 파일은 "날짜 미상"으로 따로 모아 두고 버리지 않음.

## 검증 방법

(실제 확인·판단은 사용자가 한다. 아래는 확인 방법.)

1. Everything HTTP 서버를 켜고 Python 서버 실행 → 브라우저에서 캘린더가 뜨는가.
2. **교차 확인** — 오늘 저장한 파일이 오늘 칸에 나타나는가. Everything 본체에서 같은 조건
   (`ext:... dm:오늘`)으로 검색한 개수와 캘린더 개수가 일치하는가.
3. 다른 달로 넘겨도 재요청 없이 즉시 그려지는가.
4. 파일 클릭 → 열기 / 폴더 열기 / 경로 복사가 각각 동작하는가.
5. Everything HTTP 서버를 끈 채 실행 → 안내 메시지가 제대로 뜨는가.

## 자동 테스트 범위

핵심 로직 두 개만 단위 테스트:
- Everything JSON → 날짜별 묶기 (FILETIME 변환 포함)
- config → Everything 쿼리 문자열 조립

UI와 실제 파일 열기는 위 수동 검증으로 확인한다.

## 범위 밖 (YAGNI)

- 파일 **내용** 검색 (Docufinder가 하는 일) — 필요 없음
- 직접 MFT 인덱싱 — Everything이 담당
- 다중 사용자·인증·배포 — 개인용 로컬 전용
- 생성일 표시 — 수정일만 사용
