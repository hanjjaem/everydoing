# 파일명 검색 (칸 내 필터링) — 설계 문서

작성일: 2026-06-25

## 목적

캘린더에서 파일명으로 검색해, 매칭되는 파일만 날짜 칸에 남게 한다.
파일이 2,000개가 넘어 특정 파일을 빠르게 찾기 위함.

## 동작

- 헤더에 검색 입력칸 하나.
- 입력하면 **달력 구조는 그대로**, 각 날짜 칸의 데이터가 검색어로 필터링된다:
  - 배지 개수가 매칭된 파일 수로 줄어든다. 매칭 0건인 날은 배지가 사라진다.
  - 칸을 펼치면 매칭된 파일만 보인다.
- 검색어를 지우면 전체로 복귀.
- 대소문자 구분 없이 **파일명에 검색어가 포함**되면 매칭(부분 일치).
- 서버 요청 없음 — 이미 메모리에 로드된 데이터(`data`)를 필터링한다.

## 구현 (`static/app.js`만)

- 검색어 상태 `query` 추가.
- 순수 함수 `filterFiles(files, query)` — files 배열에서 name에 query(소문자)가
  포함된 항목만 반환. query가 빈 문자열이면 files 전체를 그대로 반환.
- `render()`가 각 날짜의 파일 목록을 그릴 때 `filterFiles(dayFiles, query)` 결과를
  사용한다. 빈 검색어면 전체.
- 검색 입력 `oninput` → `query` 갱신 → `render()` 재호출.

## UI (`static/index.html`)

- 헤더에 기본 마크업의 검색 입력칸 추가(꾸밈 없음 — 디자인은 추후 일괄 적용):
  `<input id="search" type="text" placeholder="파일명 검색">`

## 서버 변경

없음.

## 에러 처리

특별히 없음. 빈 검색 = 전체, 매칭 0 = 빈 달력(자연스러운 결과).

## 검증

- 단위 테스트는 어렵다(브라우저 JS). `filterFiles`는 순수 함수이므로, Node로 간단히
  실행 검증하거나 브라우저 콘솔에서 확인한다. 핵심 동작:
  - 포함 매칭, 대소문자 무시, 빈 쿼리 = 전체.
- 수동: 검색어 입력 시 배지 수가 줄고 펼친 목록이 필터링되는가, 지우면 복귀하는가.

## 범위 밖 (YAGNI)

- 경로/내용 검색 — 파일명만.
- 정규식·다중 키워드 — 단순 부분 일치만.
- 검색 결과 별도 리스트 뷰 — 칸 내 필터링만.
